# Software Bill of Materials (SBOM)

The provider ships SBOMs in both standard formats:

- **SPDX 2.3** (JSON) — `*.spdx.json`
- **CycloneDX 1.5** (JSON) — `*.cdx.json`

Both are generated by [syft](https://github.com/anchore/syft) from the
**compiled provider binary**, so the component set is exactly what ships to
users (the runtime module closure plus the Go standard library). A source-tree
or `go.sum` scan would over-report every module in the dependency graph,
including test- and docs-only tooling; see `DEPENDENCIES.md` for that broader
module inventory and the Runtime/Tooling split.

## On demand (local / CI)

```sh
make sbom          # writes sbom/terraform-provider-truenas.{spdx,cdx}.json
VERSION=1.2.3 make sbom   # stamp a version
```

Requires `syft` on `PATH`:

```sh
go install github.com/anchore/syft/cmd/syft@latest
# or the official installer:
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh \
  | sh -s -- -b "$(go env GOPATH)/bin"
```

The `sbom/` output directory is git-ignored — SBOMs are regenerable artifacts,
not source.

## Releases

Every tagged release (`vX.Y.Z`) attaches a per-binary SBOM in **both** formats
to the GitHub release, alongside the signed archives and checksums. This is
driven by the `sboms:` block in `.goreleaser.yml`; the release workflow
installs syft via `anchore/sbom-action/download-syft`. For each built
platform binary you get:

```
terraform-provider-truenas_v<ver>_<os>_<arch>.spdx.json
terraform-provider-truenas_v<ver>_<os>_<arch>.cdx.json
```

## Scanning an SBOM for vulnerabilities

```sh
grype sbom:sbom/terraform-provider-truenas.cdx.json
```

For source-level, reachability-aware analysis of the whole module graph, use
`govulncheck ./...` instead — it reports only vulnerabilities the code
actually calls.
